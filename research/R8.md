## 3. Server entry schemas (DOC) - exact key names only as documented

- Claude Code: JSON entries under mcpServers; transports stdio, http (alias streamable-http), sse, ws (S-CC1). The docs show `claude mcp add --transport http <name> <url>` and `claude mcp add [options] <name> -- <command> [args...]` for stdio, with --env and --scope options (S-CC1).
- Codex TOML keys for stdio: command (required), args, env, env_vars, cwd. For streamable HTTP: url (required), bearer_token_env_var, http_headers, env_http_headers, auth. Common: startup_timeout_sec, tool_timeout_sec, enabled, required, enabled_tools, disabled_tools, default_tools_approval_mode (auto|prompt|writes|approve) (S-CX1).
- OpenCode: mcp.<name> with type "local" (command is an ARRAY, optional cwd, environment, enabled, timeout) or type "remote" (url, headers, oauth, enabled, timeout) (S-OC2; confirmed against schema S-OC4 definitions McpLocalConfig / McpRemoteConfig, additionalProperties false).
- Goose: extensions.<name> with type builtin|platform|stdio|streamable_http; stdio uses cmd, args, envs, env_keys, timeout; streamable_http uses uri, headers, envs, env_keys, timeout; available_tools filters tools; SSE is not supported (S-GO1).
- Hermes: mcp_servers.<name> keys command, args, env, cwd, url, headers, timeout, connect_timeout, lazy, idle_timeout_seconds, max_lifetime_seconds, enabled, tools.include / tools.exclude (S-HE1).
- Antigravity: mcpServers.<name> with command/args/env/cwd for stdio, or serverUrl (not url/httpUrl) for remote; optional headers, authProviderType, oauth, disabled, disabledTools (S-AG1).

Not-portable warning (DOC-derived): command is an array in OpenCode but string+args elsewhere; remote key is url (Claude Code, Codex, OpenCode, Hermes), uri (Goose), serverUrl (Antigravity). One shared snippet cannot be pasted across CLIs.

## 6. Startup cost (documentation evidence only)

No official page read gives measured RAM or wall-clock numbers for MCP startup in any of the seven CLIs. Measurements are UNKNOWN and must come from the plan experiment E12, not from docs.
What the docs do say qualitatively:
- Claude Code: tool search is default and defers tool schemas; discovery cache avoids connecting at startup for previously used remote servers; MCP output warning at 10,000 tokens, default cap 25,000 tokens (S-CC1). CLAUDE.md target under 200 lines; "first 200 lines or 25KB" load note for auto memory (S-CC2).
- Codex: project_doc_max_bytes default 32 KiB for AGENTS.md chain (S-CX2); grace wait 1000 ms for optional MCP servers (S-CX3).
- OpenCode: "MCP servers add to the context ... can quickly add up" (S-OC2).
- Goose: hints are tokens in every request; available_tools filter "can help reduce token overhead" (S-GO1, S-GO3).
- Hermes: stdio servers each spawn a child process tree; discovery_concurrency default 4; lazy:true avoids connecting until first call; idle_timeout_seconds recycles idle stdio servers (S-HE1). Context-file cap scales with model window, floor 20,000 chars (S-HE2).
- Antigravity: 24,000-byte per-file rule limit and 20,000-token aggregate rule budget (S-AG2).

## 9. Architecture questions from the plan

- One stdio process per CLI vs shared loopback daemon: no official page compares them. The MCP transport spec says stdio servers are launched as subprocesses by the client and, for HTTP, servers MUST validate Origin and SHOULD bind to 127.0.0.1 (https://modelcontextprotocol.io/specification/2025-06-18/basic/transports, fetched 2026-10-19). Remaining claims about daemon benefit are UNKNOWN until E12.
- Hermes documents lazy start and idle recycle for stdio (S-HE1), which reduces the per-CLI process cost without a daemon (DOC); other CLIs: UNKNOWN.
