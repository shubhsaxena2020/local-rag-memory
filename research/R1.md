# R1: Agent memory systems and practical design patterns (2026)

**Status:** Codex-authored evidence-based replacement after R1 exhausted four worker attempts without an acceptable report. This is a bounded literature scan, not an exhaustive census or independent reproduction. Sources checked 2026-10-19. Scores below are author-reported results with the named benchmark/setup; they are not directly rankable across rows.

## Summary

The field has shifted from “retrieve a similar conversation chunk” toward systems that decide what to retain, organize, revise, and retrieve over time. Common designs include agent-managed memory tools (MemGPT/Letta), structured fact extraction plus hybrid retrieval (Mem0), temporal knowledge graphs (Zep/Graphiti), linked notes (A-MEM), hierarchical memory and consolidation (MemoryOS, LightMem), and retrieval-time synthesis over episodic stores (MemFit). Newer work increasingly measures temporal updates, streaming task experience, multimodal history, and shared-memory governance.

Published results are sensitive to the answer model, judge, context visibility, data release, and task. LoCoMo, LongMemEval-S, DMR, BEAM, and proprietary task suites do not form a common leaderboard. The newest papers are largely author-reported preprints; one should prefer their methods and testable ideas over headline “SOTA” labels.

| **AgeMem** ([paper](https://arxiv.org/abs/2601.01885)) | Trains the agent policy to manage both short- and long-term memory with progressive reinforcement learning. | Authors report gains on five long-horizon benchmarks across multiple LLM backbones; exact benchmark-specific values are not used here. | Training-based method, not a drop-in local SQLite feature. | **MemVerse** ([paper](https://arxiv.org/abs/2512.03627)) | Multimodal short-term memory plus hierarchical graph-structured long-term memory and periodic distillation. | The paper reports multimodal reasoning/continual-learning experiments; the abstract does not provide a directly comparable conversational-memory score. | Relevant only if images/video/audio become first-class project memory. High scope and model cost for text-only facts. |
| **Governed Shared Memory / ArgusFleet** ([paper and evaluation](https://arxiv.org/html/2606.24535)) | Models scope, temporal supersession, provenance, and governed propagation as distributed memory-system primitives. | A 2026 arXiv v1 paper evaluates one production service: 50 depth-four provenance chains reconstructed; it also finds and remediates a sub-tenant direct-GET scope gap and identifies a deduplication/contradiction detector ordering bug. ## Reading benchmark claims correctly

- Record answer model, memory model, judge model, prompting, temperature, context visibility, retrieval depth, dataset release, and exact metric for every reported score.
- LoCoMo scores may use answer F1, BLEU, or an LLM judge; category composition and evaluator prompts can differ. LongMemEval original, cleaned, and “-S” releases/setup are not interchangeable.
- DMR is not LoCoMo or LongMemEval. Graph systems may be strong on temporal/entity queries but incur more write-time extraction and storage work.
- A score table does not establish quality on code/project memory, exact paths and identifiers, Hindi-English text, stale-fact exclusion, deletion, or scope safety.
- Large gains against a weak baseline and small gains between strong systems may both be valid in their respective papers; compare raw definitions and per-question outputs, not promotional “relative improvement” wording.
- Recent arXiv papers (including MemFit and Governed Shared Memory) may be unreviewed; report the version/date and author affiliation. Treat them as hypotheses until independently reproduced.

## Low-cost ideas to test in this project

1. Preserve immutable source/evidence with each fact, stable IDs, recorded time, and explicit supersession/retraction links.
2. Keep keyword/exact-match retrieval for paths, versions, hashes, names, and IDs; dense similarity is a poor substitute for exact identifiers.
3. Combine lexical and dense retrieval with rank fusion, then measure each component on a fixed dev split. Do not assume a graph beats a flat store at this corpus size.
4. Add source and status filters before ranking, so superseded/retracted or out-of-scope rows cannot win due to embedding similarity.
5. Separate write-time consolidation from query-time retrieval. Measure API/token/model cost of each; a low-cost query path can still have expensive ingestion.
6. Use a small labeled contradiction/update set to validate temporal behavior before adding an LLM memory manager.
7. Retain human review for automatic fact extraction and corrections until precision is measured on real session snippets.

## Recommended direction

**ADOPT as design principles:** source provenance, append-only history, explicit active/superseded/retracted states, scope enforcement, exact-match fast path, and measurable lexical+dense retrieval.

**TEST:** RRF versus weighted fusion; simple parent/summary expansion; a small model's extraction precision; optional graph neighbors on code/project questions; a single fixed-answerer claim-grounding/abstention study; and separate write-time versus read-time cost.

**REJECT for now:** selecting a vendor/system solely from reported LoCoMo/LongMemEval rank; adding an always-on graph or multi-agent consensus system without a need; using automatic LLM write/update decisions without provenance and rollback; claims of perfect accuracy, speed, or zero hallucination.

## Project fit and limitations

For this repository's laptop scale, the promising transferable baseline is a small append-only SQLite store with FTS/exact-key retrieval plus dense retrieval and RRF, source/status/scope filtering, optional verified reranking, and an explicit conflict/abstain answer contract. This is a test recommendation, not proof that the current implementation passes the plan's floors.

The project still needs local evaluation of retrieval and answer quality, latency/RAM under a quiet window, multilingual queries, retraction/update tests, and the full held-out/sealed protocol. No public score above is a substitute. All published scores and efficiency claims are author-reported on their stated benchmark and configuration; the original papers and versions must be checked again before a publication-grade comparison.
